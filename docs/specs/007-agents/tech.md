# 004 — Agents — Technical Specification

## 1. Port

`mobile/src/gamepad/application/ports/agent-control-port.ts`:

```ts
export type TranscriptPage = {
  readonly sessionId: SessionId
  readonly messages: readonly Message[]
  readonly tasks: readonly Task[]
  readonly removedIds: readonly string[]
  readonly pending: readonly PendingSubmission[]
  readonly hasOlder: boolean
  readonly hasNewer: boolean
  /** Opaque paging tokens. Core stores and returns them; it never reads them. */
  readonly olderCursor: string | null
  readonly newerCursor: string | null
  readonly liveCursor: string | null
  /** Host wall clock when the page was read, for anchoring elapsed timers. */
  readonly hostNow: number | null
}

export type PendingSubmission = {
  readonly operationId: string
  readonly text: string
  readonly state: 'pending' | 'accepted' | 'rejected' | 'unknown'
  readonly createdAt: number
}

export type TranscriptEvent =
  | { readonly kind: 'seed'; readonly page: TranscriptPage }
  | { readonly kind: 'append'; readonly page: TranscriptPage }
  | { readonly kind: 'reset'; readonly reason: string; readonly page: TranscriptPage }
  | { readonly kind: 'ended' }

export type TurnActivity = {
  readonly sessionId: SessionId
  readonly running: boolean
  readonly startedAt: number | null
  readonly toolName: string | null
}

export type BackgroundTask = {
  readonly id: string
  readonly label: string
  readonly state: 'running' | 'settled' | 'unknown'
}

export type SessionOption = {
  readonly key: string
  readonly label: string
  readonly value: string
  readonly choices: readonly TaskOption[]
}

export type SlashCommand = {
  readonly name: string
  readonly description: string
}

export type SendOutcome = 'delivered' | 'ambiguous' | 'rejected'

export type AgentControlPort = {
  readonly readTranscript: (id: ConnectionId, sessionId: SessionId,
    direction: 'tail' | 'older' | 'newer', cursor: string | null)
    => Promise<PortResult<TranscriptPage>>
  readonly observeTranscript: (id: ConnectionId, sessionId: SessionId, cursor: string | null)
    => Subscription<TranscriptEvent>
  readonly observeTurn: (id: ConnectionId, sessionId: SessionId) => Subscription<TurnActivity>

  readonly sendMessage: (id: ConnectionId, sessionId: SessionId,
    text: string, operationId: string) => Promise<PortResult<SendOutcome>>
  readonly cancelTurn: (id: ConnectionId, sessionId: SessionId,
    turnId: string, operationId: string) => Promise<PortResult<void>>
  readonly cancelBackgroundTask: (id: ConnectionId, sessionId: SessionId,
    turnId: string, taskId: string, operationId: string) => Promise<PortResult<void>>
  readonly respondToTask: (id: ConnectionId, sessionId: SessionId,
    taskId: TaskId, optionId: string, seenRevision: number, operationId: string)
    => Promise<PortResult<'accepted' | 'stale'>>

  readonly listBackgroundTasks: (id: ConnectionId, sessionId: SessionId)
    => Promise<PortResult<readonly BackgroundTask[]>>
  readonly listOptions: (id: ConnectionId, sessionId: SessionId)
    => Promise<PortResult<readonly SessionOption[]>>
  readonly setOption: (id: ConnectionId, sessionId: SessionId,
    key: string, value: string, operationId: string) => Promise<PortResult<void>>
  readonly listCommands: (id: ConnectionId, sessionId: SessionId)
    => Promise<PortResult<readonly SlashCommand[]>>
}
```

`operationId` is generated by the application layer (a use case), not by the
adapter, so a retry from the UI can reuse it. The fingerprint is the adapter's
concern.

## 2. Orca mapping

| Port method             | Orca RPC                          |
| ----------------------- | --------------------------------- |
| `readTranscript`        | `agentSession.history`            |
| `observeTranscript`     | `agentSession.subscribe` / `agentSession.unsubscribe` |
| `observeTurn`           | derived from subscribe `activity` + status feed (`006`) |
| `sendMessage`           | `agentSession.send`               |
| `cancelTurn`            | `agentSession.cancel`             |
| `cancelBackgroundTask`  | `agentSession.cancel` with `scope: 'background-tasks'`, `taskId` |
| `respondToTask`         | `agentSession.respondToApproval` \| `agentSession.respondToQuestion` |
| `listOptions` / `setOption` | `agentSession.options` / `agentSession.setOption` |
| `listCommands`          | `agentSession.commands`           |
| `listBackgroundTasks`   | `backgroundTasks` on the subscribe/history payloads |

Unmapped by choice: `agentSession.rewind`, `requestHandoff`, `handoffStatus`,
`hold`, `release`, `reveal`, `create`, `createSupport`, `ensure`,
`conversationCommand`, `close`.

### 2.1 Mutation envelope

Every mutating call carries `MutationEnvelope`
(`src/shared/rpc-contract/structured-agent-session-params.ts`):

```ts
{ sessionId
  clientOperationId          // supplied by the use case; stable across retries
  expectedRuntimeFence       // last fence seen, or null for "must not exist yet"
  payloadFingerprint }       // sha256 hex of the payload, computed by the adapter
```

Rules:

- Same operation id **and** same fingerprint → the host replays its recorded
  outcome. This is how AG-R7 / AG-AC6 hold.
- Same operation id, **different** fingerprint → conflict, never a second
  effect. The adapter surfaces this as `PortFailure{kind:'refused'}` with the
  conflict reason; the UI must not silently regenerate the id.
- The fingerprint is computed by the adapter over the exact body it sends, using
  the app's existing `@noble/hashes` dependency. No new crypto dependency.
- `expectedRuntimeFence` comes from the last `fence` observed on a subscribe or
  history reply. A stale fence is a refusal, not a retry.

### 2.2 Send

`agentSession.send` body:

```ts
{ kind: 'message', role: 'user',
  blocks: [{ type: 'text', text }] }   // 1..64 blocks, JSON ≤ 256 KiB total
```

Constants to read, never to duplicate:
`MAX_BLOCKS = 64`, `MAX_PROMPT_BYTES = 256 * 1024`
(`src/shared/rpc-contract/structured-agent-session-params.ts`).

The composer enforces the byte limit over the encoded blocks, not over the
character count (AG-AC10).

`retryUnknown: true` is set **only** on a user-initiated retry of an ambiguous
send, and only alongside the original `clientOperationId`.

### 2.3 Respond

`agentSession.respondToApproval` and `respondToQuestion` both take:

```ts
{ envelope, itemId, expectedRevision, optionId }
```

`expectedRevision` is the revision the user had on screen — a compare-and-set.
A mismatch is not an error to the user; it is "already answered / no longer
being asked", rendered as an informational state with the item's current
resolution (AG-R6, AG-AC5).

### 2.4 Cancel

```ts
{ envelope, turnId,
  scope?: 'background-tasks', taskId?,     // background-task cancel
  prompt?: { itemId, expectedRevision } }  // cancelling a pending prompt
```

Schema constraints the client must respect: a `taskId` requires
`scope: 'background-tasks'`; a `prompt` may not use background-task scope.

### 2.5 History and paging

`agentSession.history`:

```ts
{ sessionId, direction: 'tail' | 'before' | 'after', cursor?, limit? }
```

`AGENT_SESSION_HISTORY_DEFAULT_LIMIT = 40`,
`AGENT_SESSION_HISTORY_MAX_LIMIT = 200`.

Port direction `older` → wire `before`; `newer` → wire `after`. Core never sees
the wire names.

`AgentSessionHistoryPage` supplies `window.oldest`, `window.newest`,
`window.nextCursor`, `liveCursor`, `hasOlder`, `hasNewer`, `removedItemIds`,
`submissions`, and `hostNow`. The adapter maps:

| Port field      | Source |
| --------------- | ------ |
| `olderCursor`   | `window.oldest` |
| `newerCursor`   | `window.newest` |
| `liveCursor`    | `liveCursor` |
| `removedIds`    | `removedItemIds` |
| `pending`       | `submissions` |
| `hostNow`       | `hostNow` |

An `AgentSessionHistoryResult` with `ok: false` is a **reset**, not a failure:
it carries a bounded tail page. The adapter emits `TranscriptEvent{kind:'reset'}`.

`liveCursor` is what lets AG-R12 hold: attach at the tail, then subscribe from
`liveCursor` with no second full read.

### 2.6 Subscribe

`AgentSessionSubscribeEvent` (`src/shared/agent-session-wire.ts`):

| Wire event  | Port event | Handling |
| ----------- | ---------- | -------- |
| `snapshot`  | `seed`     | replace the local journal |
| `batch`     | `append`   | apply idempotently; items carry current reduced state, so re-applying converges |
| `reset`     | `reset`    | discard and reseed from the carried page |
| `end`       | `ended`    | stream closed by the host |

Fence rules:

- A `batch` with a `fence` lower than the last seen fence is **dropped by the
  adapter**. Core never sees it.
- `snapshot` and `reset` always carry a fence and always set it.
- A missing `fence` on a `batch` (mixed-version host) inherits the last known
  fence rather than clearing it.

`activity` is additive and ephemeral: it never creates or advances a journal
row. It feeds `observeTurn` only.

`commands` is `undefined` when unchanged and `null` to clear. Do not conflate
the two.

### 2.7 Journal item → domain

`AgentJournalRenderItem.body` variants
(`src/shared/agent-session-journal-types.ts`):

| Journal item  | Domain |
| ------------- | ------ |
| `message`     | `Message{body:{kind:'user'\|'assistant'}}` |
| `toolCall`    | `Message{body:{kind:'tool', state: running\|completed\|failed}}` |
| `diff`        | `Message{body:{kind:'diff', path, added, removed}}` |
| `approval`    | `Task{prompt:{kind:'approval'}}` |
| `question`    | `Task{prompt:{kind:'question'}}` |
| `turn`        | not a message — feeds `TurnActivity` |
| `status`      | not a message — feeds `Agent` (`006`) |

`AgentJournalResolution` (`pending` / `resolved` / `cancelled`) maps directly to
`Task.resolution`. A resolved task stays in the transcript; it is not removed.

Item revision for compare-and-set is carried adapter-side, keyed by item id, and
supplied back on `respondToTask`. It is deliberately not in the domain `Task`:
core has no business holding a wire revision. The port takes `seenRevision` as a
number the UI got from the same read that produced the `Task`, via a
`TaskRevisionRegistry` in the application layer.

## 4. Transcript reducer

`state/transcript-reducer.ts` is the only place journal state is assembled.

```text
seed(page)    → items = page.items                (replace)
append(page)  → upsert page.items by id
                 remove page.removedIds
                 merge page.pending by operationId
reset(page)   → items = page.items, emit reset notice
```

Invariants, each with a test:

1. `append(append(x, b), b) === append(x, b)` — idempotent (AG-AC2).
2. Order comes from the host cursor order; the reducer never sorts.
3. A tombstoned id never reappears from an older page.
4. A pending submission is replaced by the real message when the message with
   the matching operation id arrives.
5. Reset clears tombstones as well as items.

## 5. Mutation lifecycle

`state/pending-mutation-registry.ts`:

```text
begin(operationId, payload)   → record { operationId, fingerprintInput, state: 'pending' }
settle(operationId, outcome)  → 'delivered' | 'rejected'
lose(operationId)             → 'ambiguous'   (no reply, socket closed, or timeout)
retry(operationId)            → re-send with the SAME operationId, retryUnknown: true
```

The registry is persisted with local UI state so an ambiguous send survives an
app restart and can still be resolved by the user (AG-R8).

Reuse `mobile/src/transport/rpc-delivery-ambiguity.ts` for the classification;
do not re-derive "did this land".

## 6. UX rules

- The intervention card is rendered above the transcript and is never
  scrolled out of reach while a task is pending.
- Elapsed-time displays are computed as `hostNow + (localNow - localAtRead)`,
  never from the device clock alone.
- The composer is disabled, with a stated reason, when: the connection is down,
  the host refused the capability, or the session is `exited`.
- A `tool` message shows its name and state; the raw tool input is behind a
  disclosure, not inline, and is byte-bounded before rendering.
- Reset notice copy is informational ("the host reloaded this conversation"),
  not an error.
- Every string that renders a state uses the vocabulary in `000-foundation`.

## 7. Failure modes

| Condition | Behaviour |
| --------- | --------- |
| Subscribe unsupported | fall back to polled `history` with `after` from the last cursor; label the surface as polled |
| `commands` unsupported | no command affordance, no error (AG-AC12) |
| `options` unsupported | options sheet hidden |
| Fence conflict on a mutation | refusal with "this session moved on"; re-read before retrying |
| Fingerprint conflict | refusal; never regenerate the operation id automatically |
| Send times out | `ambiguous`; explicit user retry only |
| Reset storm (repeated resets) | back off resubscribe; show a persistent notice after the third reset in a minute |
| Transcript item too large | truncate for display with an explicit "truncated" marker and a byte count |
